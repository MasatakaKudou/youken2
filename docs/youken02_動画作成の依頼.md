YouTubeチャンネル「要件定義からやります」#2 の動画を作りたいです。実測が終わったので、検証の結果をもとに、企画と台本から進めてください。

## 材料
- 検証のまとめ：`docs/youken02_検証まとめ.md`（仕組み、検証の内容、詰まりと乗り越え方、結果の数字）
- 元のデータ：`mac/results/*.json` と `mac/logs/`（数字はここから引いてください）
- 実装：`mac/server.py`、`mac/prompts.py`、`mac/batch.py`

## 進め方
1. youken-kara-planning スキルで、構成と台本を作る。台本ができたら、確定する前に私に見せてください
2. 台本が確定したら、youken-kara-production スキルで、デモ・ナレーション・映像の書き出し・投稿の準備まで進める

## 動画の軸にしたいこと（案なので、もっと良い軸があれば提案してください）
- 「コメントを全部褒め言葉にする基盤」を、要件定義から作って実測した
- 「やわらかくする」スキルでは、100回中100回、褒め言葉にならなかった（冷たいのは1回だけ）。「やわらかくする」と「褒める」は別の要件だった
- 負荷試験では、褒め率 99.00%（200件中、褒めていないまま届いたのは2件）。その代わり、「重複してる」「N+1になってる」という指摘の中身は消えた
- 悪い変更（v13）を5%に出したら、バーンレート10000倍で、161.4秒で自動ロールバックした
- それでも、変換前の冷たいコメントは p50 で約27秒、見えたままだった

## 守ってほしいこと
- 数字は、まとめ（またはログ）にあるものだけを使い、丸めたり作ったりしないでください。並列などの条件も一緒に書いてください（C と D は並列16、表示時間は1件ずつ）
- 実験B（判定の精度）はまだ実行していないので、結果として扱わないでください
- 詰まり（Gemini の429、聞き返し、C が途中で止まった、D でロールバックが起きなかった）は、隠さずに見せ場として使ってかまいません
- `mac/.env` の中身（トークン、smee の URL など）は、画面にも台本にも出さないでください
- `src/userSearch.js` はわざと SQLインジェクションを入れたデモ用のコードなので、そのことがわかる見せ方にしてください
